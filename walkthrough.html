SQL 谋杀之谜

你能查出凶手是谁吗？

SQL 城出人命了！《SQL 谋杀之谜》既是一门自学 SQL 概念与命令的课程，也是给熟练 SQL 玩家准备的推理游戏——一桩耐人寻味的凶案等着你。

给 SQL 新手的图文教程

如果你 SQL 用得顺手，可以跳过这些讲解，直接上机试试。下面我们会介绍几个基础 SQL 概念，以及刚好够你破案的那点细节。想系统入门 SQL，可以看 Select Star SQL。

一起凶案发生了，警探需要你的帮助。警探把案情报告交给了你，你却不知怎么把它弄丢了。你隐约记得那是一起谋杀案，发生在 2018 年 1 月 15 日，地点在 SQL 城。先到警局数据库里把对应的案情报告调出来。

破案的所有线索都埋在一个庞大的数据库里，你得靠 SQL 在这张巨大的信息网里找路。第一步是从警局数据库里取出那份对应的案情报告。下面我们会在较高的层面上解释你需要知道的命令；随时准备好，就可以动手改写示例、拼出自己的 SQL 命令去搜线索了——任何一个代码框里都可以运行任意 SQL，不管框里原来写的是什么。

先搞清楚几个概念

SQL 是什么？

SQL 是 Structured Query Language（结构化查询语言）的缩写，它是与关系型数据库和表打交道的方式，能让我们从中提炼出具体而有意义的信息。

等等，关系型数据库又是什么？

「数据库」这个词没有唯一的标准定义。大体上说，数据库就是管理信息的系统。不同数据库对数据施加的结构程度不一样；数据结构化得越好，人和计算机就越能高效地处理这些数据。

关系型数据库大概是最出名的一类。它的核心是表（table），很像电子表格：每一列有列名和数据类型（文本、数字等），每一行则是这张表「关于」的某个具体实例。所谓「关系型」，指的是表与表之间的数据如何连接——这部分有一套专门的规则。

ERD 是什么？

ERD 是 Entity Relationship Diagram（实体关系图）的缩写，用图形表示一个数据库里各张相关表之间的关系。下面就是本数据库的 ERD。图中每个框顶部是表名（加粗），左边是列名，右边是对应的数据类型（全大写）。图上还画了金色钥匙图标、蓝色箭头和灰色箭头：金色钥匙表示该列是所在表的主键（primary key），蓝色箭头表示该列是所在表的外键（foreign key）。

什么是查询？

要是直接去看数据库里的数据，你会发现表大得吓人：数据点实在太多，靠一行行翻是翻不出需要的信息的。那该怎么办？

这就是查询（query）的用处。查询是我们为了从数据库取数据而构造的语句，读起来大体像自然英语。拿本数据库练几条吧。下面每个框都可以点「运行」来执行框里的查询，也可以直接在页面上改，继续探索。（SQL 命令不区分大小写，但习惯上把关键字写成大写，读起来更清楚。换行和空格也可以随意用，让命令更好读。多数数据库系统要求语句以分号「;」结尾，不过这个网页里的执行器比较宽容。）

一条 SQL 查询由哪些元素组成？

一条 SQL 查询可以包含：

  • SQL 关键字（比如上面的 SELECT 和 FROM）
  • 列名（比如上面的 name 列）
  • 表名（比如上面的 person 表）
  • 通配符（比如 %）
  • 函数
  • 具体的筛选条件
  • 等等

SQL 关键字

SQL 关键字用来在查询中指定动作。它们不区分大小写，但我们建议关键字全用大写，这样跟查询的其余部分一眼就能区分开。几个常用的关键字：

SELECT

SELECT 让我们取出指定的列：

  • *（星号）：跟在 SELECT 后面，表示取出表里所有列；
  • 列名：想取特定列，就把列名写在 SELECT 后面，用逗号隔开。
FROM

FROM 用来指定我们关心哪张（或哪几张）表；要选多张表，就把表名列出来，用逗号隔开。（不过在学 JOIN 关键字之前，你可能会对结果感到意外——那是后面的事。）

WHERE

查询里的 WHERE 子句用来按具体条件筛选结果。

AND 关键字用来把多个筛选条件串起来，结果必须同时满足每一个条件。（还有 OR 关键字，只要满足其中任意一个条件，那一行就会被返回。）

通配符与其他模糊匹配

有时你只知道所需信息的一部分，SQL 照样能应付。代表未知字符的特殊符号叫「通配符」，SQL 支持两种。最常用的是 %。

在查询字符串里放一个 %，SQL 就会返回这样的结果：除了通配符所在的位置可以是任意内容（或者什么都没有）之外，其余部分完全匹配。例如， 'Ca%a' 能匹配 Canada 和 California。

另一种通配符用得少一些，是 _，意思是：只要 _ 那个位置恰好有且只有一个字符（不管是什么字符），文本其余部分匹配即可。所以 'B_b' 能匹配 'Bob' 和 'Bub'，但匹配不到 'Babe' 或 'Bb'。

重要：用通配符时不要用 =，要用 LIKE。

SQL 也支持数值比较，比如 <（小于）和 >（大于）。你还可以用 BETWEEN 和 AND——这些对文字同样有效。

前面说过 SQL 命令不区分大小写，但 WHERE 里配合 = 和 LIKE 使用的取值是区分大小写的。有时你并不知道文本在数据库里到底是怎样存的。SQL 提供了几个函数来抹平这种差别，叫 UPPER() 和 LOWER()——看名字大致就能猜到它们干什么，尤其在下面这个框里试一试之后。

再深挖一点

SQL 聚合函数

有时你想问的问题没那么简单，不是「找出符合条件的那一行」就完事。你可能会问「谁年纪最大？」「谁最矮？」这类更复杂的问题。聚合函数能帮你回答。其实上面你已经学过一个了：COUNT。

有驾照的人里，年纪最大的是多大？数据量小的时候，肉眼扫一眼也就出来了；可 drivers_license 表里有几千条记录。（想知道到底有多少，用 COUNT 试试！）光盯着列表是找不到答案的。

SQL 提供几个好用的聚合函数：

MAX
求最大值
MIN
求最小值
SUM
计算指定列的数值之和
AVG
计算指定列的数值平均值
COUNT
统计指定列的取值个数

找最小值和最大值还有另一种办法，而且能顺带看到更多数据：你可以控制结果的排序。这很直观——用 ORDER BY 加上列名就行。数据一多就有点难办了！（人们认真做 SQL 的时候会用比这个网页系统更好的工具。）默认情况下 ORDER BY 按「升序」排列（从小到大，或从 A 到 Z），你也可以明确写 ASC 表示升序，或者用 DESC 反过来。

到这里，你掌握的 SQL 已经够你找出那两位目击者了。动手试试！

把数据连起来

连接表

到目前为止，我们要问的问题都只看一张表就能回答。但如果一个问题需要同时用到两张表的数据呢？这就要靠 JOIN 了。

资深的 SQL 玩家会用几种不同的 JOIN——你可能听过 INNER、OUTER、LEFT、RIGHT。这里只讲最常见的一种：INNER JOIN。因为它太常见，写 SQL 的时候可以把 INNER 省掉。

最常见的连接方式是用主键和外键。记不清这是什么，或者想看看本数据库里各表之间的键关系，就回头翻上面的 ERD。其实任意列都能做连接，但键列针对快速返回做了优化。用这个交互式 SQL 系统演示，比讲文字更清楚。

有时你想连的不止两张表。SQL 允许你在一条查询里连多少张表都行。
